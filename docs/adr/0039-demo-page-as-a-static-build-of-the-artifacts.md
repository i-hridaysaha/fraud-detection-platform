# 0039: The demo is a static page built from the committed artifacts, not a live service

- **Status:** accepted
- **Date:** 2026-09-13
- **Stage:** 9, addendum

## Context

The platform needs a demo that can sit on a personal website: a page a reader opens and that
shows the lifecycle in motion, without cloning the repo, downloading the data or starting a
service. Stage 9 left the lifecycle demo as a script (`scripts/lifecycle_demo.py`), an artifact
(`reports/lifecycle_demo.json`) and one figure. The script needs the raw files, which are under
Kaggle competition rules and cannot be redistributed (ADR 0003), 306 seconds of compute, and a
registry under `mlruns/`. None of that can run on a static host.

Evidence rule 1 holds for the demo as for everything else: every number a reader sees comes
from a committed artifact plus one command that regenerates it. A demo that computes its own
numbers at view time, or that carries numbers typed in by hand, breaks that rule.

## Options considered

**A hosted scoring service with the model behind it.** Rejected for now. The service (stage 8)
needs the shipped model, a feature store and a host that runs Python; the interesting part of
the platform is not one score but the loop that keeps the model honest, and a live endpoint
shows the score and hides the loop. It also needs rows to score, and the only rows the model
was built for cannot be published. A hosted service can be added later without touching this
page.

**A screen recording or a notebook export.** Rejected. Neither is interactive, neither ties a
number to its artifact, and both go stale silently when the artifact is regenerated.

**A self-contained HTML page built by a script from the committed artifacts, tested against a
fresh build.** Chosen. `scripts/demo_page.py` reads nine artifacts under `reports/`, inlines
the fields the page renders as one JSON block, and writes `docs/demo/index.html` with its own
CSS and script; no library, no data, one stylesheet host for the typefaces with a declared
fallback. The page replays the fourteen cycles of `reports/lifecycle_demo.json`: the drift job
per batch close, the decay job per matured batch, the retrain decision, the four gate verdicts
and the rollback drill, and states what the run does not establish, in the words of
`docs/monitoring.md` section 5.

## Decision

The demo is `docs/demo/index.html`, regenerated by `make demo-page`. It renders only what the
artifacts hold: `tests/test_demo_page.py` compares the committed page with a fresh build byte
for byte, compares the embedded JSON with the extractor's output, checks every cycle, gate
verdict and rollback field against `reports/lifecycle_demo.json`, checks the headline numbers
against the artifacts they name, checks the constants against `lifecycle.py`, and checks that
the builder imports nothing beyond the standard library. A regenerated artifact makes the test
fail until the page is rebuilt, so the page cannot drift from the run it describes.

The page lives under `docs/` so that it can be served from the repository's docs folder when
the repository goes public in stage 10, and copied as one file to any other host before that.

## Evidence

`reports/lifecycle_demo.json` and the eight artifacts named in the page's sources table, each
with its `regenerate_with`; `make demo-page`; `tests/test_demo_page.py`. The choice of a static
build over a service is judgement, not measurement.

## Consequences

- The page shows the loop, not a live score. A reader who wants to score a row still runs the
  service locally (`make serve`, `docs/serving.md`).
- The page is exactly as current as the artifacts. `make reproduce` ends with `demo-page`, so a
  full rebuild rebuilds the page; a partial rebuild that regenerates `lifecycle_demo.json`
  without running `make demo-page` fails the test suite.
- The em dash check now covers `*.html`, since the page carries prose.
